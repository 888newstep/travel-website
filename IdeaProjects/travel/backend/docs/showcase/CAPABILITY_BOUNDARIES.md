# 项目能力边界

## 1. 项目定位

本项目是面向秋招答辩、企业与学校技术交流的全栈工程化展示项目，不将自己包装成已经商业化运营的旅游平台。展示重点是 Java 微服务、认证授权、幂等性、并发一致性、第三方 API 治理、RabbitMQ 可靠消费和可复现压测。

固定约束如下：

- 不使用 Milvus 或其他向量数据库。
- 不建设短信计费、余额、套餐或账单能力。
- 交通距离、时长和道路拥堵只接受高德开放平台结果，不用直线距离、固定速度或随机值伪装实时交通。
- Win11 本机运行 MySQL、Redis 和 JMeter；RabbitMQ 使用云端实例。
- 缺少可信数据源时返回不可用、空结果或明确错误，不生成固定评分、固定节省时间、固定设施和随机趋势。

## 2. 状态定义

| 状态 | 含义 |
|------|------|
| 已验证 | 有单元测试、集成验证或真实并发证据，可作为答辩主线 |
| 条件可用 | 代码已接线，但需要外部密钥、云服务或白名单；必须先完成现场预检 |
| 有限可用 | 能工作，但数据范围、算法语义或存储形态有限，演示时必须说明边界 |
| 明确不可用 | 当前主动返回不可用或没有可信数据源，不应包装为完整功能 |
| 遗留占位 | 仍存在固定返回或伪能力代码，不纳入展示，后续应删除或改接真实数据源 |
| 不在范围 | 产品和技术范围明确排除 |

## 3. 核心业务能力

| 能力 | 状态 | 当前真实语义 | 失败或降级语义 | 主要证据 |
|------|------|--------------|------------------|----------|
| 用户登录与 JWT | 已验证 | BCrypt 校验密码，Gateway 校验 JWT，服务内再次建立认证上下文 | Token 缺失或无效返回 401；JWT 密钥不合规时 Gateway 拒绝启动 | `GatewayAuthTest`、`JwtAuthenticationFilterTest` |
| 对象所有权与角色权限 | 已验证 | 路线优化、资料、收藏、评论、文件等写操作从认证上下文取当前用户；管理员路径单独授权 | 越权返回业务错误或 403 | Controller/Service 单元测试、`WebSecurityConfig` |
| HTTP 幂等 | 已验证 | 已认证写请求可携带 `Idempotency-Key`；Redis 保存处理中状态和原响应 | 处理中 409、同键异请求 409、Redis 故障 503、完成请求原样重放 | 100 并发与 Redis 故障演练 |
| 注册/重置验证码 | 有限可用 | Redis Lua 原子校验并一次性消费验证码 | 默认没有短信通道；仅显式开启 `CAPTCHA_DEMO_MODE` 时向本地演示返回验证码 | `UserServiceImplTest`、安全配置 |
| 景点、城市、餐厅查询 | 已验证 | 数据来自 MySQL；评分使用数据库聚合，餐厅按城市过滤 | 数据库无记录时返回空结果，不生成虚构详情 | attraction-service 测试 |
| 景点点评 | 已验证 | 同一用户对同一景点使用数据库 UPSERT，唯一键收敛为一条记录 | 并发更新仍保留同一点评 ID | 100 并发 JMeter，最终一条记录 |
| 景点实时状态 | 有限可用 | 只表示数据库中的最新状态快照 | 没有历史明细时，历史平均和近 7 天接口返回 HTTP 503 / `20007` | `RealtimeStatusControllerTest`、治理计划 |
| 路线 CRUD、查询、复制和可见性 | 已验证 | MySQL 持久化，写操作执行所有权校验 | 不存在或越权明确失败 | route-service Controller/Service 测试 |
| 路线优化应用 | 已验证 | 支持完整显式顺序，或按天基于本地经纬度做最近邻排序；分布式锁、行锁、两阶段更新、唯一键共同保证一致性 | 无坐标、日程不完整、跨路线或重复位置明确拒绝 | 100 并发 JMeter，历史仅一条 |
| 优化类型 | 已验证 | `/route-optimization/apply` 只开放 `distance`，兼容别名 `shortest` 并统一记录为 `distance` | `time/cost/balanced` 等未实现目标明确返回 `17003`，不包装为多目标优化 | `RouteOptimizationServiceImplTest` |
| 遗传算法 TSP | 有限可用 | 仓库保留 `GeneticAlgorithmTSP` 作为算法学习与实验实现 | 不是当前 `/route-optimization/apply` 一致性主链路，不能把实验类直接描述为线上最优解 | 算法源码与单元测试 |
| 路线收藏 | 已验证 | 分布式锁内切换状态，数据库唯一键兜底，缓存同步失效 | 同键并发只执行一次；Redis 故障 fail-closed | 100 并发与 Redis 故障演练 |
| 路线评论与点赞 | 已验证 | 评论按路线和发布状态查询；点赞行为持久化到 `user_collection`，计数 SQL 原子增减 | 唯一键阻止同用户重复行为 | 100 用户并发点赞，最终计数 100 |
| 游记 | 有限可用 | 支持发布、修改、删除、浏览、点赞和收藏 | 尚无游记评论明细表，评论区和评论接口不属于当前能力 | collection-service 测试、评论数重置迁移 |
| 文件管理 | 有限可用 | 独立 file-service 提供上传、下载、分类和版本接口 | 当前主要是本地资源存储展示，不等同于对象存储、高可用文件平台 | `ResourceFileServiceImplTest` |

## 4. 外部数据与消息能力

| 能力 | 状态 | 当前真实语义 | 现场要求与边界 |
|------|------|--------------|----------------|
| 高德驾车路线 | 条件可用 | 按路线中相邻景点逐段调用高德 `driving` API，聚合距离、时长和 `tmcs` 路况 | 必须配置真实 `AMAP_API_KEY`；缺 Key、无路径、超时或配额失败时 `dataAvailable=false`，不伪造降级值 |
| 高德结果缓存 | 已验证 | 成功路线结果短期写入 Redis，减少重复外呼 | 缓存不能把失败结果包装成成功；演示前应清理目标路线缓存以证明真实外呼 |
| RabbitMQ 可靠通知 | 条件可用 | 云 RabbitMQ、publisher confirm、mandatory returned、manual ACK、三档 TTL 重试、DLQ | 必须配置云 broker 并显式开启 topology/producer/consumer；当前真实云端验收仍待凭据 |
| MQ 消费幂等 | 已验证 | Redis `PROCESSING/COMPLETED` 快速路径 + `notification.source_message_id` 唯一键 | Redis 抢占失败时 NACK requeue；数据库唯一键是最终兜底 |
| MQ 状态表 | 有限可用 | 可记录 `PENDING/DISPATCHED/CONFIRMED/RETURNED/FAILED/RETRYING`，并提供补偿抢占 Mapper | 当前没有接线中的定时扫描补偿任务，不能宣称“消息表自动定时重投” |
| Nacos | 有限可用 | Windows 本地脚本使用内置 Nacos 做注册发现 | Docker Compose 明确禁用 Nacos，Gateway 使用容器 DNS 静态路由 |

## 5. AI 能力

| 能力 | 状态 | 当前真实语义 | 展示口径 |
|------|------|--------------|----------|
| 通义千问文本对话/问答 | 条件可用 | 配置 `QWEN_API_KEY` 后调用 DashScope，Redis 缓存部分问答；服务端不伪造置信度、优化分数或快捷建议 | 仅作为生成式助手；缺 Key、关闭服务或供应商失败统一返回 HTTP 503 / `5006` |
| 通义千问行程文本生成 | 条件可用 | 目的地、天数、偏好和预算共同进入提示词及缓存键，生成文本/JSON 字符串 | 结果未与本地景点、营业时间和高德路线做强一致校验，不作为可执行订单或真实交通方案 |
| 本地约束排程 | 有限可用 | `/ai/advanced/plan` 根据请求中的必去景点和时间约束做本地排程 | 实现是约束调度器，不是大模型推理；成本和优化分数保持空值 |
| 百度 URL 图像识别 | 条件可用 | 远程图片通过显式域名白名单、私网拦截、禁止重定向、类型和 10 MiB 限制后调用百度 AI | 需要 `BAIDU_*` 和 `AI_IMAGE_ALLOWED_HOSTS`；真实外呼未验收前不作主演示 |
| 高级攻略、预算和安全评分 | 明确不可用 | 没有可信价格、安全和攻略数据源，服务主动抛出“无数据”业务异常 | 不展示，不生成固定北京攻略、固定预算或固定安全分 |
| 个性化推荐 | 明确不可用 | 只读取已有缓存；无数据源时返回空列表 | 不把空结果包装成推荐引擎 |
| 上传图片综合分析/相似景点 | 不在范围 | 固定结果实现、上传入口及遗留 DTO 已删除；当前只保留真实百度 URL 图像识别 | 未接本地景点相似度数据源前不恢复该入口 |
| 多模态问答、推荐与搜索 | 不在范围 | Controller、Service、DTO 和前端页签已删除；项目不使用 Milvus，也没有图片送入多模态模型的链路 | 不宣称图文理解、图片向量检索或多模态推荐 |

## 6. 明确不在范围

- Milvus、Embedding 向量库、RAG 知识库和图片向量检索。
- 短信计费、账户余额、账单、套餐、支付与退款。
- 酒店、门票、交通票务的库存、订单和结算。
- 真实历史客流预测；当前只有景点状态快照。
- 自建地图、固定交通数据或随机拥堵模拟；交通只接受高德 API。
- 将大模型生成内容当作经过核验的安全、价格、开放时间或交通事实。

## 7. 演示红线

1. 不恢复已删除的固定图片分析和伪多模态入口；图像展示只使用真实百度 URL 识别链路。
2. 没有 `AMAP_API_KEY` 时展示“明确不可用”和本地桩测试证据，不伪造高德成功截图。
3. 没有云 RabbitMQ 凭据时展示拓扑、单元测试和失败预检，不声称已完成云端实测。
4. 路线应用优化只描述为按经纬度执行最近邻距离排序，不宣称时间、费用或综合目标最优。
5. 不把 Compose 描述为包含 Nacos 或本地 RabbitMQ。
6. 不把验证码演示模式描述成短信平台，更不增加短信计费逻辑。
